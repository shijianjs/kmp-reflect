<ktjs-features section-title="What it gives you" tinted>

<ktjs-feature icon="lucide:boxes" title="Metadata, in plain Kotlin">The processor writes `KmpClass`, `KmpFunction`, `KmpProperty` … as ordinary source, so every backend compiles them — no runtime reflection, no class loading.</ktjs-feature>

<ktjs-feature icon="lucide:tag" title="Opt-in per class">Only classes marked `@KmpReflect` or implementing `KmpReflectable` are recorded, and scanning only ever sees those.</ktjs-feature>

<ktjs-feature icon="lucide:terminal" title="Call it like reflection">`KmpClasses.of<Person>().function("greet")?.invoke(person, "Hello")` — including `suspend` functions through `invokeSuspend`.</ktjs-feature>

<ktjs-feature icon="lucide:copy" title="Generated proxies">A `@KmpReflect` interface gets a proxy class that forwards every call to a `KmpInvocationHandler`, instead of `java.lang.reflect.Proxy`.</ktjs-feature>

<ktjs-feature icon="lucide:file-archive" title="Resources without a runtime">Configured directories are read at compile time and inlined as Base64, with MIME type and size, so a browser or a native binary reads them the same way.</ktjs-feature>

<ktjs-feature icon="lucide:layers" title="Every KSP target">JVM, JS, Wasm and Kotlin/Native all get the same generated code; the Gradle plugin registers the processor per target for you.</ktjs-feature>

</ktjs-features>
