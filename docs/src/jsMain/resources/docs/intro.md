# kmp-reflect

Kotlin Multiplatform has no reflection: `commonMain` code cannot ask a class for its name, its members
or its annotations, and Kotlin/JS cannot do it at all. `kmp-reflect` moves that work to compile time. A
KSP processor walks the classes you opt in, writes their metadata as ordinary Kotlin, and hands you an
API shaped like a small, typed subset of `java.lang.reflect`.

```kotlin
KmpReflection.register(DemoReflection)                       // generated module object

val person = KmpClasses.of<Person>()
    .constructor(3)
    ?.new("Ada", 36, "hidden") as? Person

KmpClasses.of<Person>().function("greet", 1)?.invoke(person, "Hello")  // "Hello, Ada!"
```

Nothing is loaded, scanned or allocated at runtime: the metadata is already there, and every call it
describes is an inlined Kotlin call generated next to the class it belongs to.

## What you get

- **Class metadata** — name, package, kind, visibility, modifiers, supertypes, type parameters,
  constructors, functions, properties, enum entries, companions and nested classes.
- **Annotation data** — annotation types and arguments, readable without the platform's annotation
  support. Scanning works because the annotations were written into the metadata.
- **Invocation** — constructors, functions and property accessors that perform the real Kotlin call.
  Members whose signature cannot be expressed (a `suspend` function, a generic one) are still
  described, and simply report themselves as not invokable.
- **Dynamic proxies** — a generated class per reflected interface, forwarding every call to your
  handler. This is how you get `java.lang.reflect.Proxy` semantics without the JVM.
- **Inlined classpath resources** — path, MIME type and bytes embedded into generated code, so the
  same lookup works on every target without a file system or a network.

Everything above is generated as ordinary Kotlin source, so it works on **every backend KSP can feed**:
JVM, Kotlin/JS, Kotlin/Wasm and Kotlin/Native. See [Platforms](guide/platforms.md).

## Naming

Every public type is prefixed with `Kmp` — `KmpClass`, `KmpFunction`, `KmpClasses` — because the
library also runs on the JVM, where `java.lang.reflect` types are already imported everywhere. A name
like `KmpClass` never collides with `Class`, and it makes the switch between the two obvious in code
that uses both.
